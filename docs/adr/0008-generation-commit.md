# 0008. Copy-on-write версии объектов и единый корень commit

- **Статус:** Принято (Accepted), решением владельца SN-002-R2
- **Дата:** 2026-11-12
- **Scope:** SN-002, Q-02/Q-06/Q-09.
- **Частично заменяет ADR 0004:** уточняет и заменяет физическую схему имён/размещения из ADR 0004;
  сохраняет решение «каталог, отдельный зашифрованный файл на запись».

## Контекст

Атомарная замена файла не делает атомарной транзакцию item+blob+header.
Без аутентифицированного inventory нельзя отличить удаление объекта от его отсутствия.
Предыдущий root нужен для восстановления, но автоматический fallback маскирует rollback.

## Решение

Неизменяемые файлы с отдельным случайным write ID, encrypted manifest всех активных
объектов и один текущий `vault.json`. Заголовок связывает manifest hash, generation,
родительский header hash и оба slots через HMAC. Публиковать dependencies раньше root,
под эксклюзивной OS-блокировкой; сохранять предыдущий root и его dependencies.

[Протокол](../storage-protocol.md) задаёт точки сбоя, uncertain commit, права,
symlink/reparse ограничения, проверку backup/restore и GC. [Формат](../vault-format.md)
сохраняет `vault.json`, `items`, `blobs`, `.lock`, `.backup`, добавляет `manifests`/`.tmp`.
Физическое имя теперь write ID, стабильный logical ID хранится в authenticated envelope.
В текущем inventory — одна версия каждого logical item; история физически отдельно.

При повреждении не выбирать старый root молча. Восстановление — полная проверка выбранного
snapshot и копия в новый каталог с явным подтверждением отката. Нет обещания обнаруживать
полный rollback без внешнего доверенного состояния. GC не опирается только на время.

## Альтернативы

| Подход | Причина выбора/отказа |
|---|---|
| Отдельные replace без транзакции | Недостаточная согласованность нескольких файлов |
| Authenticated journal | Возможен, но требует сложного replay/compaction и ещё одного формата |
| COW + manifest/root | Выбран как проверяемый протокол без перезаписи unchanged blobs |
| Полная копия каталога на каждую запись | Проще снимок, неприемлемый лишний I/O/место |
| SQLite/WAL | Меняет ADR 0004 и поставку; не нужен для этого дизайна |

## Последствия и утверждение

Больше файлов и временного места; serial readers/writers в M1/M2; отдельные платформенные
адаптеры. Внешняя папочная синхронизация активного vault не поддерживается до sync ADR.
Семантика power loss зависит от qualified filesystem; Windows/APFS требуют испытаний,
а unsupported writable storage отклоняется. Не выдавать File.Replace за доказательство.

SN-002-R2 утверждает этот архитектурный протокол. В ADR 0004 добавлена ссылка на частичную
замену физического layout; исторический текст сохранён. Принятие не доказывает реализацию
или гарантии ОС. SN-003 требует отдельного разрешения владельца.
