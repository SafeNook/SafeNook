# 0004. Хранилище как каталог с файлом на запись

- **Статус:** Принято
- **Дата:** 2026-10-21

## Контекст

Хранилище должно синхронизироваться через git, файловые сервисы (Syncthing, Dropbox, Nextcloud) и позже через собственный сервер. При одном зашифрованном файле любое изменение переписывает весь файл, и одновременные правки на двух устройствах дают конфликт, который невозможно слить без полной расшифровки.

## Решение

Хранилище — каталог:

```
vault/
├─ vault.json        # заголовок: версия формата, key slots
├─ items/<uuid>.item # одна зашифрованная запись
├─ blobs/<uuid>.blob # вложения
├─ .lock
└─ .backup/
```

Каждая запись шифруется отдельно, имена файлов — случайные UUID. Подробности — в `docs/vault-format.md`.

## Альтернативы

- **Один файл** (как KeePass KDBX): проще копировать вручную, но конфликты синхронизации только на уровне всего файла.
- **SQLite с шифрованием (SQLCipher)**: нативная зависимость, бинарный файл плохо живёт в git.

## Последствия

- Слияние конфликтов возможно на уровне записей; git-синхронизация (этап 4a) почти бесплатна.
- Утечка метаданных: видно количество записей, их размеры и время изменения. Фиксируется в модели угроз.
- Разблокировка расшифровывает все записи — приемлемо до десятков тысяч записей; при необходимости позже добавляется зашифрованный индекс.
- Экспорт/бэкап «одним файлом» делается отдельной командой (`nook export --encrypted`).
