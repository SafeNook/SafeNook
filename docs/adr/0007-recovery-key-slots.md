# 0007. Обязательный recovery slot и независимые ключи доступа

- **Статус:** Предложено (Proposed)
- **Дата:** 2026-11-12
- **Scope:** SN-002, Q-03/Q-04/Q-08; [реестр](../SN-002-DECISIONS.md).

## Контекст

Владелец подтвердил recovery key уже в M1. Его обязательность не обсуждается повторно.
Нужно выбрать проверяемую реализацию жизненного цикла, не связывающую восстановление
со знанием потерянного пароля. Принятые ADR 0002/0003 сохраняют выбор Argon2id и AES-GCM.

## Предлагаемое решение

Случайный VK256 оборачивается двумя независимыми AES-GCM slots: password через Argon2id
и HKDF, recovery через независимый случайный RK256 и HKDF. Ровно один slot каждого вида.
Полный заголовок защищён HMAC ключом из VK; AAD каждого slot привязывает его к vault,
epoch, slot ID и всем его параметрам. Точные байты: [формат](../vault-format.md).

Создание vault и замена RK публикуются только после доставки и явного подтверждения
сохранения нового RK. Интерактивно — повторный ввод полного ключа; в скриптах — отдельный
защищённый файл, readback и явное принятие ответственности. Base32+40-bit checksum
обнаруживает опечатки, но не является дополнительной криптографической защитой.
[Recovery и I/O](../recovery-and-io.md) задают полный контракт.

Смена пароля сохраняет recovery slot побайтно, без знания RK. Потерянный RK заменяется
после аутентификации паролем. Удаление recovery slot без замены запрещено. При утрате
пароля RK позволяет создать новый password slot без перешифрования объектов.

Замена slot не отзывает уже скопированный VK: для защиты будущих объектов нужна отдельная
ротация VK с новым epoch и полным перешифрованием. Для неё нужны оба credentials либо
новые подтверждённые credentials. Старые backup остаются доступными по старым ключам.
Recovery не восстанавливает потерянные ciphertext/header и не заменяет backup.

## Альтернативы

| Вариант | Оценка |
|---|---|
| Только пароль | Не соответствует обязательному recovery в M1 |
| RK из пароля | Не обеспечивает независимое восстановление; отклонён |
| Случайный RK оборачивает VK | Рекомендуется: простая независимая ветвь доступа |
| Shamir/социальное восстановление | Сложнее UX и протокол; отдельная будущая задача |
| Escrow на сервере | Противоречит независимости локального M1; не требуется |
| Много пользовательских slots | Возможно позже; увеличивает парсер, перебор и жизненный цикл |

## Последствия и утверждение

Обязательность recovery уже утверждена владельцем. Утвердить нужно двухслотовый формат,
текст RK/UX, ограничения KDF и правила смены/ротации. Независимые vectors, review и
негативные сценарии из [плана](../SN-002-VERIFICATION.md) обязательны до выпуска.
Этот ADR не утверждает wire format автоматически и не разрешает прикладной код.
