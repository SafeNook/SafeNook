# ADR 0010 — Переносимый контейнер зашифрованного backup

Статус: **Принято (Accepted)**. Утверждено владельцем для реализации SN-003D1.

## Контекст

SN-003D1 требует переносимого archive и строгого restore. Действующий storage-protocol
определяет только backup-каталог и прямо откладывает однофайловый формат. Принятые ADR
0007–0009 не задают упаковку archive. Реализовывать её неявно нельзя.

## Предложение

Принять [точную спецификацию v1](../portable-backup-format.md): SNBACKUP, заголовок
контейнера 24 байта, существующий header 414 байт, ограниченные кадры зашифрованных
объектов без путей, сжатия и новой криптографии. Один выбранный root и точный набор
его зависимостей, включая tombstones. Проверять все AEAD tags, в том числе всех blobs.

Restore сохраняет исходные header/slots/IDs/ciphertext и публикует root последним только
в новый каталог. Ошибка после публикации означает Indeterminate. Свежий локальный lock
не импортируется. Backup и restore остаются за закрытым production-write gate; тесты
используют внутренний qualification harness. Параметры криптографии vault не меняются.

## Альтернативы и последствия

Каталог уже определён, но не удовлетворяет проверкам однофайлового archive. ZIP/TAR
добавляют пути, варианты метаданных и лишнюю поверхность парсера. Минимальное framing
требует собственных тестов формата, но не собственной криптографической конструкции.
Новый MAC контейнера дублировал бы существующую аутентификацию и потребовал нового
криптографического review; вместо этого применяется строгое соответствие authenticated
inventory и exact EOF. Полный rollback и отзыв старых копий по-прежнему не гарантируются.

Раздел backup storage-protocol дополнен ссылкой на этот формат;
не заменять ADR 0007–0009 и не объявлять Windows durability квалифицированной.
Реализация parser/writer/restore разрешена владельцем; production-write gate остаётся закрытым.
