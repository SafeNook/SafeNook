# 0002. NSec (libsodium) для Argon2id и Ed25519

- **Статус:** Принято
- **Дата:** 2026-10-21 (предложено), 2026-10-21 (принято по итогам спайка F-4)

## Контекст

Нужны примитивы, которых нет в BCL .NET 10:

- **Argon2id** — функция вывода ключа из мастер-пароля. От скорости реализации зависит, какие параметры можно выбрать: медленная реализация вынуждает брать меньше памяти/итераций, а атакующий всё равно перебирает быстрой нативной.
- **Ed25519** — подпись для ssh-agent (этап 3).

Требование: работа под Native AOT на всех RID из матрицы этапа 2: win-x64, win-arm64, linux-x64, linux-arm64, linux-musl-x64, osx-arm64, osx-x64.

## Решение

[NSec](https://nsec.rocks) **26.4.0** — .NET-обёртка над libsodium **1.0.22**. Даёт Argon2id и Ed25519 с нативной скоростью; libsodium хорошо проверена.

- Пакет: `NSec.Cryptography` 26.4.0. Он требует libsodium `[1.0.22, 1.0.23)` и при инициализации проверяет версию библиотеки (26.4); с другой libsodium NSec не стартует.
- Целевой способ поставки — **libsodium, статически слинкованная в бинарник `nook`** на всех RID (см. «Упаковка»). Динамическая libsodium из NuGet-пакета работает везде и остаётся запасным вариантом.
- Параметры Argon2id ограничены возможностями libsodium: **p = 1, соль ровно 16 байт** (см. «Параметры Argon2id»).

## Результаты спайка F-4

Код: [`spikes/NSecAotSpike`](../../spikes/NSecAotSpike/), workflow: [`.github/workflows/spike-nsec-aot.yml`](../../.github/workflows/spike-nsec-aot.yml), прогон: [run 39661659575](https://github.com/SafeNook/SafeNook/actions/runs/39661659575) (все 15 джобов зелёные).

Каждый бинарник проверяет:

- Argon2id на трёх тест-векторах из libsodium 1.0.22: `test/default/pwhash_argon2id.c` / `.exp` (`tv[0]`, `tv3[2]`, `tv3[4]`). Это Argon2id v1.3, одна полоса, без secret и associated data. Вектор RFC 9106 неприменим: он использует secret, associated data и p=4, а libsodium их не поддерживает. Векторы phc-winner-argon2 с `"somesalt"` тоже: соль 8 байт, а libsodium требует 16.
- Ed25519 на RFC 8032, §7.1, TEST 1: вывод открытого ключа, подпись, проверка эталонной подписи, отказ на испорченной подписи.
- Границы параметров Argon2id (см. ниже).
- Время Argon2id: p=1, t=3; один прогрев, затем среднее из 3 запусков.

Каждый RID собран дважды: **shared** — libsodium из NuGet-пакета рядом с бинарником; **static** — libsodium вшита в бинарник через `DirectPInvoke` + `NativeLibrary`. Для static на Linux и macOS libsodium собирается в CI из исходников релиза 1.0.22. На Windows берётся официальная статическая `libsodium.lib` из `libsodium-1.0.22-msvc.zip`. Оба архива проверяются подписью minisign (ключ из документации libsodium) и закреплённым SHA-256. Static-бинарник запускается скопированным в пустой каталог, без чего-либо рядом.

- Публикация без единого предупреждения trimming/AOT и нативного линкера на всех 14 сборках; `TreatWarningsAsErrors` включён.
- Static добавляет к бинарнику ~115–360 КБ; это меньше, чем отдельная libsodium. `libsodium.dylib` в NuGet-пакете — универсальный (x64 + arm64) файл на 1,7 МБ.
- В shared-варианте libsodium не попадает в таблицу импортов исполняемого файла (`ldd`, `otool -L`): .NET загружает её при первом P/Invoke. В static-варианте у бинарника остаются только системные зависимости: libc/libm, musl libc, libSystem и системные фреймворки macOS.

> **Замеры времени ориентировочные.** Они сделаны на shared-раннерах GitHub, где производительность плавает между запусками и машинами. Расхождения shared/static в обе стороны (osx-arm64 −26 %, osx-x64 +22 %) — шум, а не эффект линковки. Для калибровки параметров по умолчанию нужны замеры на реальных машинах (F-6).

Для ориентира: на x64 m=256 MiB, t=3 занимает ~0,3–0,4 с, на arm64-раннерах ~0,7–0,9 с. Цель «0,5–1 с» из roadmap на быстрой x64-машине потребует m порядка 512 MiB–1 GiB либо больше проходов.

### Параметры Argon2id

Ограничения NSec 26.4.0 повторяют проверки libsodium (`crypto_pwhash/argon2/pwhash_argon2id.c`). Спайк подтвердил каждую границу на всех RID:

| Параметр | Допустимо | Примечание |
|---|---|---|
| Parallelism (p) | **только 1** | p=2 и p=4 → `ArgumentException`. libsodium не принимает этот параметр и всегда использует одну полосу. Рекомендация RFC 9106 (p=4) недостижима. |
| Память (m) | 8 KiB … 4 TiB − 1 KiB (64-бит); до 2 GiB на 32-бит | Задаётся в KiB, в libsodium уходит в байтах. |
| Проходы (t) | 1 … 2³² − 1 | |
| Соль | **ровно 16 байт** | 8, 15, 17, 32 байта → `ArgumentException`. |
| Длина выхода | ≥ 16 байт по Argon2 | Более короткий выход NSec принимает, но молча считает 16 байт и обрезает. Это не то же, что Argon2 с T < 16, потому что длина тега входит в H0. Для SafeNook неважно: KEK = 32 байта. |
| Secret, associated data | не поддерживаются | Привязка KEK к хранилищу делается через AAD при обёртке VK (§5 roadmap), а не через Argon2. |

Следствие для спецификации формата (F-12): в `vault.json` фиксируем `parallelism: 1` и соль 16 байт. Поле `parallelism` оставляем в формате, чтобы при смене реализации можно было поднять p без новой версии формата. Компенсация p=1 при калибровке: целевое время набирается **сначала памятью, затем проходами**; минимум `m=64 MiB, t=3` не меняется.

### Упаковка нативной библиотеки

**Shared (как есть в NuGet).** `dotnet publish` кладёт рядом с бинарником `libsodium.dll` / `libsodium.so` / `libsodium.dylib`. Работает на всех 7 RID, но:

- **Windows:** `libsodium.dll` из NuGet импортирует `VCRUNTIME140.dll` (`dumpbin /dependents` на win-x64 и win-arm64). Сам AOT-бинарник её не требует: он линкует vcruntime статически, а UCRT (`api-ms-win-crt-*`) входит в Windows 10+. На чистой машине понадобился бы **Visual C++ Redistributable** либо `vcruntime140.dll` рядом.
- **macOS:** второй Mach-O-файл нужно подписывать и нотаризовать вместе с бинарником.
- Пакеты для менеджеров (nfpm, Homebrew, Scoop, winget, AUR) должны ставить два файла и следить, чтобы версия libsodium совпадала с NSec.

**Static (рекомендуется).** Один файл без зависимостей сверх системных, проверено на всех 7 RID:

```xml
<DirectPInvoke Include="libsodium" />
<NativeLibrary Include="path/to/libsodium.a" />  <!-- libsodium.lib на Windows -->
```

Плюс таргет, который убирает shared-libsodium из NuGet-ассетов: `NativeCopyLocalItems` / `RuntimeTargetsCopyLocalItems` с именем `libsodium`. Это возможно потому, что NSec вызывает libsodium через `[LibraryImport("libsodium")]` без собственного `DllImportResolver`.

- Linux (glibc и musl), macOS: `./configure --disable-shared --enable-static --with-pic` из релизного tar.gz; на macOS `MACOSX_DEPLOYMENT_TARGET=12.0`, иначе линкер предупреждает о более новой целевой версии.
- Windows: `libsodium/<x64|ARM64>/Release/v143/static/libsodium.lib` из официального `-msvc.zip`. Статический бинарник **не импортирует `VCRUNTIME140.dll`**: VC++ Redistributable пользователю не нужен.

### Открытые вопросы для этапа 2

- Перенести сборку libsodium в релизный pipeline: закрепить версии тулчейна и образов, кэшировать артефакт, по возможности добиться воспроизводимости.
- Windows: в спайке использована официальная предсобранная статическая библиотека (подписанная), а не сборка из исходников. Решить, достаточно ли этого, или собирать из исходников через MSBuild (`builds/msvc`).
- Флаги сборки libsodium из исходников: на linux-arm64 static был чуть медленнее shared из NuGet (в пределах шума раннеров). Сверить флаги оптимизации со сборкой в NuGet-пакете.
- Обновления: NSec и libsodium обновляются только вместе (NSec проверяет версию при старте). Dependabot обновит NSec, но не версию libsodium в pipeline — нужна проверка в CI, что они совпадают.
- Лицензии: добавить уведомления libsodium (ISC) и NSec (MIT) в поставку.

## Альтернативы

- **Managed Argon2id** (например, Konscious.Security.Cryptography): без нативных зависимостей, но заметно медленнее → слабее параметры. Ed25519 всё равно нужен отдельно. Остаётся запасным вариантом, если какой-то будущей платформе libsodium не подойдёт.
- **Своя реализация** — нет: собственная криптография исключена.
- **PBKDF2 из BCL** — только как запасной вариант, если ни одна реализация Argon2id не работает под AOT; параметры не ниже 600 000 итераций SHA-256.

## Последствия

- Argon2id и Ed25519 берутся из NSec; AEAD и HKDF — из BCL ([0003](0003-aead-cipher.md)), так что ядро шифрования не зависит от нативной библиотеки.
- Параметры Argon2id: p=1, соль 16 байт; калибровка — память, затем проходы. Пример в roadmap §5 обновлён.
- Тесты Argon2id (F-5) используют векторы libsodium, а не RFC 9106.
- Для одного бинарника libsodium линкуется статически; это добавляет сборку libsodium в релизный pipeline (этап 2).
