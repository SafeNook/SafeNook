# 0002. NSec (libsodium) для Argon2id и Ed25519

- **Статус:** Предложено (ждёт спайка F-4)
- **Дата:** 2026-10-21

## Контекст

Нужны примитивы, которых нет в BCL .NET 10:

- **Argon2id** — функция вывода ключа из мастер-пароля. От скорости реализации зависит, какие параметры можно выбрать: медленная реализация вынуждает брать меньше памяти/итераций, а атакующий всё равно перебирает быстрой нативной.
- **Ed25519** — подпись для ssh-agent (этап 3).

Требование: работа под Native AOT на win-x64/arm64, linux-x64/arm64/musl, osx-x64/arm64.

## Решение (предлагаемое)

[NSec](https://nsec.rocks) — .NET-обёртка над libsodium. Даёт Argon2id и Ed25519 с нативной скоростью; libsodium хорошо проверена.

Решение принимается после спайка F-4:

1. Консольное AOT-приложение, вычисляющее Argon2id (m=64 MiB, t=3, p=4) и подпись Ed25519.
2. Публикация `PublishAot=true` на всех RID из матрицы CI.
3. Проверка: собирается без предупреждений trimming, нативная библиотека libsodium подхватывается (рядом с бинарником или статически), результаты совпадают с тест-векторами RFC 9106 и RFC 8032.
4. Замер времени Argon2id для сравнения с managed-альтернативой.

## Альтернативы

- **Managed Argon2id** (например, Konscious.Security.Cryptography): без нативных зависимостей, но заметно медленнее → слабее параметры. Ed25519 всё равно нужен отдельно.
- **Своя реализация** — нет: собственная криптография исключена.
- **PBKDF2 из BCL** — только как запасной вариант, если ни одна реализация Argon2id не работает под AOT; параметры не ниже 600 000 итераций SHA-256.

## Последствия

- При принятии: рядом с бинарником может появиться нативная libsodium; это учитывается в упаковке (этап 2).
- AEAD остаётся на BCL ([0003](0003-aead-cipher.md)), чтобы ядро шифрования не зависело от нативной библиотеки.
