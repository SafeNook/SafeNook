# 0006. Самостоятельный local-first vault и приоритет developer secrets

- **Статус:** Принято
- **Дата:** 2026-11-11
- **Основание:** прямые решения владельца в задаче SN-001.

## Контекст

SafeNook возник из опыта PasswordGeneratorCLI. Исторический roadmap включал одноразовый импорт
старого формата, а SSH, файлы и агент объединял в поздний выпуск. Владелец уточнил продуктовые границы.

## Решение

1. SafeNook — самостоятельное local-first open-source хранилище секретов для разработчиков.
2. Полностью исключить импорт из PasswordGeneratorCLI: не реализовывать совместимость,
   миграцию, чтение старого формата или соответствующие тестовые fixtures.
   Исторические упоминания допустимы для объяснения происхождения.
3. Приблизить поддержку SSH-ключей, age-идентичностей и небольших файлов к первой практически полезной версии.
4. Сохранить .NET, Native AOT, кроссплатформенность и независимость криптографического ядра от UI.
5. Не начинать реализацию сервера или GUI до стабилизации локального ядра.
6. Выбранное направление фирменного стиля — Vault Monogram.

## Альтернативы

Исторический импорт старых данных отклонён владельцем. Откладывание всех developer secrets
до выпуска после 1.0 не соответствует новому приоритету.
Конкретные способы поддержки SSH/age/файлов и номера версий этим решением не выбираются.

## Последствия

- F-11 исключена, её ID не используется повторно; убраны связанные команды и критерии готовности.
- Хранение SSH/age/файлов планируется отдельно от ssh-agent и фонового процесса.
- Предлагаемая последовательность milestones вынесена в [roadmap](../ROADMAP.md);
  архитектурные альтернативы — в [вопросы SN-001](../SN-001-ARCHITECTURE-QUESTIONS.md).
- ADR 0001–0005 сохраняют силу; этот ADR не меняет криптографию, wire format или UI framework.
- Версии, критерии milestones и конкретные алгоритмы интеграции требуют отдельного согласования.
- SN-001 не разрешает SN-002 или реализацию кода без согласования результатов.
